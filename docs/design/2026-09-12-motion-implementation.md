# Bandi 视觉与动效实施记录

日期：2026-09-12。依据：[前端视觉与动效审计](2026-09-12-motion-visual-audit.md)，源码基线 `e46b8ad`。本轮只优化现有动漫空间，保留深色影厅、主题变量、原生导航和播放器／下载语义。

## 已实施

| 流程 | 当前行为 | 边界 |
| --- | --- | --- |
| 找资源弹窗 | 单集、全集、首页 Hero 与今日更新均将目标数据和 `open` 分开；等关闭动画结束再清理。快速重开取消过期清理，关闭后尝试归还焦点。 | 沿用 Radix 与现有锁滚样式；未改 RSS 和入队逻辑。 |
| 开关与按压 | 开关滑块用可重定向的 `translate` transition 取代固定起点 keyframe；卡片与主播放按钮增加轻量按压反馈。 | 首帧静态；减少动态效果时不位移。未引入拖拽或新动效库。 |
| 我的追番卡片到详情 | 仅网格卡片试行同源跨文档 View Transition，原生 `<a>` 仍决定导航。封面独立变形，标题和操作不参与拉伸。卡片点击前把筛选写入当前历史项，并记录卡片、滚动和焦点；返回时按 URL 与卡片位置恢复。一次性标记防止旧记录串到“最近添加”等其他入口。 | 缺图、封面未真正可见、超时、不支持或减少动态效果时走原生导航／短淡入；其他页面和待看链接不纳入试验。详情 Hero 改用 `AnimeCover` 的现有失败占位。此链路尚待用户视觉验收。 |
| 番剧库首屏 | 只压缩番剧库 Hero；搜索、评分排序与已选条件保持可见，年份／分类／来源／类型／地区进入“更多筛选”。骨架同步，筛选功能完整保留。 | 我的追番与影视区 Hero 尺寸未变；默认 TV／日本以可移除条件显示。 |
| 首页 Hero | 下一张封面解码后再提交换片；1600ms 超时或图像失败时进入暗色占位。标题、信息和操作区协调交接，按钮位置稳定。 | 外部资料不阻塞页面，轮播悬停／焦点暂停保持。 |
| 今日／预告与卡片进场 | 两个方向互逆、同时交接，内容高度变化由布局动画接住；卡片 orbit 只在该身份首次可见时触发，不因筛选重复播放。 | 未增加持续装饰；高频筛选保留快速反馈。 |
| 文字与减少动态效果 | 关键进度、筛选提示改用更清楚的次级文字层级；长中文卡片标题可读两行。Hero、追番网格与今日／预告的 Motion 位移接入减少动态效果。 | 全局主题色、局部番剧色和低优先级 muted token 未统一改亮。 |

`animation-routing` 和 `transitions-dev` 用于沿用现有 `t-*`、Radix 生命周期与 motion token；`apple-design` 用于按下即反馈、从当前开关位置反向及返回空间关系；`motion-web` 的 handfeel 判据用于区分卡片跟随与回正，未在缺少实测问题时替换为自写弹簧；`impeccable` 用于番剧库首屏、字阶与材质层次的静态复核；`emil-design-eng`／`review-animations` 只对本次改动检查高频降噪、起点、可中断性和 reduced-motion；`find-animation-opportunities` 只复核已触及的状态突变，未追加新场景。

## 未扩展的候选

- 详情到播放器、影视空间和全站导航：单卡链路需先通过用户视觉验收与可靠性检查；播放器视频实例和进度保存不为动效改动。
- 卡片指针跟随参数、双壳主按钮与播放器渐进磨砂：当前没有可靠的实测问题或封面裁切证据，保持原实现；若用户验收指出具体手感问题，再做有界调整。
- 全页流体、液体光标、持续光效、替换 Motion：与当前高频操作和深色影厅层级不符。

## 第二轮有界补查（2026-09-13）

本轮仅复核已试行的 `/library` ↔ `/anime/[id]` 原生跨文档转场，不扩到播放器、影视或全站路由。以下是源码与定向检查结论；真实视觉与交互继续由用户验收。

### A. 页头稳定性：保留当前结构

`RootLayout` 只挂一次 `DesktopTitlebar`，主布局只挂一次 `Nav`；两者位于 `<main>` 外。桌面标题栏 44px、导航及 spacer 64px，库页与详情页使用同一几何锚点，没有源码证据表明页头重复挂载或高度跳变。root old/new 仍各用 160ms 淡变，所以页头标题及 Nav 选中线是否出现可感知叠影，只能由真实画面判断。本轮不给 `main` 或页头增加独立快照名，避免为了未实测的疑虑引入嵌套快照。详情 Nav 选中线依赖异步状态，若用户看到晚出现，应单独处理该状态，不靠整页加动画掩盖。

### B. 封面与内容接力：局部修正

共享名 `bandi-cover` 只给 `AnimeCover` 外壳，卡片标题、状态和详情操作没有参与 450ms 几何拉伸。此前 root 160ms 已让详情 Hero 文字与操作很早显露；现在仅当源卡和目标 Hero 的图片都真正可见时，给详情 Hero 内容独立命名：进入延迟 110ms、用 320ms 轻微上移淡入，返回只用 120ms 淡出。背景与固定页头维持 root 160ms，封面维持 450ms。没有把整个 `<main>` 或长正文做成截图组。首页 `HomeHero` 的轮播仍由自身图片预备、背景交叉淡化和标题／操作 `AnimatePresence` 管理，不混入库页跨文档时序。

### C. 图片与能力降级：补齐双端就绪协议

原有 `imageReady()` 已检查真实 `<img>` 的完成状态、自然尺寸、视口位置及祖先可见性；`AnimeCover` 缺图、失败或 15s 超时会转占位。新加一次性 `COVER_KEY`：源卡可见才记录；目标 Hero 同样可见才命名封面和详情内容。源已命名而目标不就绪时调用 `skipTransition()`，避免单侧 450ms 残影；源未就绪则不命名，保留 root 的短淡入。返回同样记录源 Hero 就绪状态，目标卡不就绪或筛选上下文不匹配时跳过单侧共享动画。无 View Transition、减少动态效果、存储不可用时，普通 `<a>` 仍负责到达，返回标记按既有一次性流程清理。

140ms hover/focus 预取未采用：本链路保留原生硬导航，详情为动态服务端页并可能触发外部资料匹配；当前没有能证明预取可复用且不增加请求的实现依据。不会让点击等待预取。

### D. 证据与验收

[原审计勘误](2026-09-12-motion-visual-audit.md) 已补充：VibeHub 的桌面卡片共享快照是固定 450ms 曲线，移动详情滑动另有 `430/42/.78` 弹簧；共享的是截图而非迁移 DOM；2026-09-06 镜像与 2026-09-12 线上属于不同部署。未把固定版 CSS 参数当作线上逐帧实测。

本轮定向导航用例 6/6 通过，覆盖双端就绪、单端缺图、返回缺图、减少动态效果、旧快照和存储失败；`npx tsc --noEmit` 与 `git diff --check` 通过。`npm run desktop:direct` 已完成生产构建与免安装副本重建，`release\win-unpacked\追番中心.exe` 存在，桌面 `追番中心.lnk` 的目标和工作目录准确。未运行真实视觉、帧率、配对 Safari 或窗口点击验收。

用户查看时可分三段：

1. **页头**：在 1180px 与 1280px 的“我的追番”点一张已加载封面的网格卡，再用详情返回；看标题栏、空间切换、导航选中线是否重影或移位。Web 模式只看导航。
2. **封面与正文**：观察封面是否先开始展开、详情标题与操作随后出现且不被拉伸；返回时内容先退、封面回原卡。首页 Hero 点缩略图另看文字／按钮交接，两条流程不能混为一项通过。
3. **缺图与降级**：选未加载或缺图卡片进入／返回，确认仍能到达且没有单侧封面残影；再用系统“减少动态效果”重复，检查大位移是否消失。真实慢网、BFCache 与 Safari 的结果请单独记录，源码检查不能代替。

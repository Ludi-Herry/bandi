# Bandi 前端视觉与动效对比分析
日期：2026-09-12 · 源码基线：e46b8ad · 性质：设计审计，不是实施方案或性能验收

Bandi 最有价值的升级，是把“发现一部作品 → 展开详情 → 进入观看 → 返回原处”做成连续的体验，同时保留封面主导、深色影厅和克制微光的现有方向。当前局部微动效已经较丰富；继续加特效的收益，低于补齐退出、连续操作和视觉层级。

## 证据范围与限制

- 已检查 Bandi 当前源码、设计规范、首页／番剧详情／番剧库基线截图，以及参考项目和知识库材料。

- 本轮没有运行中的 Bandi 产品窗口供实测；未启动应用、构建、安装、改业务代码或操作个人媒体数据。帧率、快速操作时的实际跳帧和主观弹簧手感尚未实测。

## 你喜欢的东西，具体落到哪些判据

知识库直接记录的个人偏好包括：弹簧优先于机械匀速、克制节制、物理关系可解释，以及 Motion Core 的实体按钮／双壳卡片、Rare UI 的少见但有明确状态价值的组件。来源：[个人偏好档案](H:/LLM本地知识库/实体/陆凌华_设计与技术偏好档案.md:152)、[近期明确偏好](H:/LLM本地知识库/实体/陆凌华_设计与技术偏好档案.md:196)。

[高级感与丝滑体验判据](H:/LLM本地知识库/UIUX设计/高级感与丝滑体验-可执行判据.md:10) 是知识库综合方法，不能把其中每条都当作你的逐字评价。它把高级感落在层级、材质、字阶和真实状态，把丝滑落在即时响应、连续空间、可打断和降噪。这与本次你明确点名的一镜到底相互吻合。

| 偏好 | Bandi 中适合的落点 | 避免的误用 |
|---|---|---|
| 有来处、有归处的空间变化 | 封面展开为详情、返回定位、弹窗退回触发上下文 | 每换页都从底部统一飞入 |
| 可解释的弹性 | 开关、按压、局部选择器，拖动时跟随输入 | 整屏标题和正文一起反复弹 |
| 少而准的层级与材质 | 封面主角、操作浮层、内嵌笔记区，各层职责不同 | 所有面板都加同样的玻璃、描边和 glow |
| 稀有但有状态价值的交互 | 从选集到观看、状态变化、保留位置的返回 | 在批量筛选和下载表格上复刻作品集表演 |
| 克制的真实质感 | 实体按钮轻微下沉、封面图层和操作层分离 | 把背景流体、磁吸光标、RGB 色散一起铺全站 |

知识库还记录你喜欢暖白轻界面，说明“深色”不是高级感的唯一条件。但 Bandi 已有明确影厅方向，本轮没有证据支持推翻它。mikes.cv 的底部渐进磨砂可作为播放器控制栏的局部候选；不建议马上把多层实时模糊铺到长列表。Motion Core 的双壳构造适合试在主播放按钮或设置控件，不宜让每张番剧卡都变厚。

时长按 [知识库时间尺度](H:/LLM本地知识库/UIUX设计/高级感与丝滑体验-可执行判据.md:72) 分工：按压／hover 90–180ms，常规切换 180–300ms，空间展开 450–600ms。这些是调试起点；不能把“越慢越高级”或“所有动画都小于 300ms”当成统一规则。

## Vibe Hub 的“一镜到底”到底做了什么

本地参考保留的是构建产物。主要证据位于 [导航逻辑 JS](K:/网站复刻/vibe-hub-clone/_next/static/chunks/281-a07ed0dab1914a97.js:1) 与 [转场 CSS](K:/网站复刻/vibe-hub-clone/_next/static/css/ac130e4c0bde6e16.css:1)；都是压缩单行，可按下列函数／选择器检索。

| 机制 | 参考中的真实实现 | Bandi 应学习的部分 |
|---|---|---|
| 同一对象连续变形 | 卡片与详情 Hero 在切换前后共用 viewTransitionName="morph"；group 为 450ms、cubic-bezier(.22,1,.36,1) | 保留对象身份和空间位置，不只是新页面淡入 |
| 主体接力 | detail-body-enter 延迟 110ms、进入 320ms，y 从 9px 回到 0、scale 从 .997 到 1 | 封面先建立空间，文字随后接住，不让所有区域同时抢注意 |
| 原路返回 | 打开前保存卡片 id 和 top，返回按新位置与原 top 差值恢复滚动，再反向 morph | “返回到刚刚看的那张卡”是动效的一部分 |
| 相邻内容有方向 | goDetail 的 next／prev 对应互逆方向；detail-body 横移 16vw，350ms | 前进／返回要能从运动方向分辨，但 Bandi 可用更小位移 |
| 防止过期操作 | token 判断异步准备结果；cancelPendingNavigation 取消旧请求的提交资格；忙碌状态避免重复进入 | 动画和资料加载共用明确状态，不让旧结果覆盖新选择 |
| 能力回退 | 检测 startViewTransition 与 reduced-motion，不适用时直接同步切换 | 动画是增强层，导航可用性始终成立 |

**关键区别：这段进出使用固定时长与贝塞尔曲线，没有 stiffness／damping／mass 物理弹簧。** 你喜欢的手感可以同时来自良好的曲线和空间连续性，没必要把所有转场都改成弹簧。

参考也有不能原样搬的地方：它会等待条目资源准备，且已有 opening 卡片时拒绝重复进入；这提供稳定性，但不等于“随时无条件重定向”。Bandi 有外部资料和视频加载，不能让进入详情无限等待它们。参考找不到原卡片时回到顶部，Bandi 可以用更温和的当前位置回退。以上是基于两者场景差异的设计建议。


## 优先级总表

“高”表示与本次体验目标相关性高，不是安全或产品故障等级。成本是相对工作量。

| 顺序 | 类型 | 位置与现状 | 建议与体验收益 | 成本 |
|---|---|---|---|---|
| 1 | 确定性实现问题 | 找资源弹窗被父级直接卸载 | 分开“开关状态”和“当前集数”，退场完成再清理目标；关闭也有完整收尾 | 小 |
| 2 | 手感风险 | 开关从固定关键帧起点播放 | 从当前位置响应反向操作；回弹少、收敛快，连续点也连贯 | 小—中 |
| 3 | 现有取舍上的设计升级 | 卡片／Hero／播放入口多为原生跳转，没有贯通的共享封面链路 | 先做一个卡片到详情的有界试验，保留可靠跳转兜底 | 大，分阶段 |
| 4 | 视觉结构升级 | 番剧库高标题区＋完整筛选矩阵 | 收起次要筛选，保留已选摘要，让首屏真正用于选番 | 中，需视觉确认 |
| 5 | 编排升级 | Hero 背景、标题、元数据、按钮各自换场 | 图片准备好再切；标题与信息协同交接，按钮位置稳定 | 中 |
| 6 | 已确认的转场编排 | 今日／预告两个方向都向左退、从右进，且等待退场 | 前后方向互逆，减少空档，控制内容高度变化 | 小—中 |
| 7 | 视觉层级升级 | 次要文字很暗、卡片叠加多种反馈 | 关键进度更清楚；一次交互只突出一种主要反馈 | 小—中 |
| 8 | 兼容与一致性 | CSS 已降级，部分 Motion 位移没有使用降级判断 | 把减少动态效果接到实际页面位移，不只处理 CSS | 小 |

## 1. 先补“退出”，能最快感受到完整性

**源码证据：** [HomeHero.tsx](H:/追番网站-desktop-exe/src/components/features/HomeHero.tsx:409) 用 `sourceTarget &&` 挂载弹窗，关闭立即 `setSourceTarget(null)`；[EpisodeGrid.tsx](H:/追番网站-desktop-exe/src/components/features/EpisodeGrid.tsx:266) 的单集和全集弹窗也采用条件挂载。子组件 [EpisodeSourceDialog.tsx](H:/追番网站-desktop-exe/src/components/features/EpisodeSourceDialog.tsx:252) 原本使用 Radix，CSS 也已有关闭动画，但整个父子树先被移除。

建议保留弹窗和内容目标，让 Radix 的关闭生命周期先完成，再清理数据。焦点回到原触发按钮，背景滚动条不跳；复用现有 250ms 进入／150ms 退出起点即可，不需要马上换库或加重弹性。快速关开时，应撤销过时的清理动作，避免新开的内容被旧回调清空。

另一个应单独验证的点是菜单／弹窗开合关键帧：[globals.css](H:/追番网站-desktop-exe/src/app/globals.css:1364) 从固定 scale 与 opacity 起点播放。完整开合已有处理，不能误报“全部弹窗都没退出”；这里只是快速反向时可能重新起跑，需要运行复核。

## 2. 弹簧应当支持“中途改主意”

**2026-09-21 已处理：** `MotionSwitch` 已按 shadcn/ui 的 Radix Switch 结构重写。旧实现让业务页面分别设置轨道 padding、圆点尺寸和位移，曾出现 24px 轨道容纳 `1px 边框 + 4px 上下 padding + 16px 圆点 = 26px` 的必然错位；现统一为可验算的成对几何，并使用可中途反向的 `transition-transform`。业务页面只保留颜色或 `size="sm"` 差异。

后续可反复切换的选中指示器继续沿用同一原则：位移只由组件自己计算，业务层不得各写一套 travel 值。弹性主要放在短距离的操控件，长文、整页和播放器画面保持稳定。

**验收动作：** 开关还没到终点就反向、连续点击三次、键盘切换。最终状态正确，滑块从当前视觉位置转向，不先跳回两端。不要只看一遍完整开启来判断丝滑。

## 3. 最接近“一镜到底”的升级：卡片展开为详情

**当前情况：** [AnimeCard.tsx](H:/追番网站-desktop-exe/src/components/features/AnimeCard.tsx:85)、[HomeHero.tsx](H:/追番网站-desktop-exe/src/components/features/HomeHero.tsx:316)、[PlayButton.tsx](H:/追番网站-desktop-exe/src/components/features/PlayButton.tsx:51) 都有原生链接；[主布局](H:/追番网站-desktop-exe/src/app/(main)/layout.tsx:66) 直接输出页面 children，当前没有覆盖这条链路的共享封面过渡。

这并非可以直接“修正”的错误。[BrowseCard.tsx](H:/追番网站-desktop-exe/src/components/features/BrowseCard.tsx:19) 与 [SpaceSwitcher.tsx](H:/追番网站-desktop-exe/src/components/features/SpaceSwitcher.tsx:7) 明确说明：原生跳转是为避免曾出现的 soft navigation 失效。设计简报虽然提出共享封面过渡，实际可靠性取舍仍然有效。

**可审阅的目标体验：**

1. 点击卡片立即有轻量按下反馈。
2. 封面从原位置展开，周围列表退为背景；标题保持清晰，不随着整张截图拉伸。
3. 详情骨架接住封面；简介、剧集、制作人员独立加载，不让外部资料请求决定动画何时开始。
4. 返回时收回原卡片；原季度、筛选、滚动位置和焦点仍在。
5. 来源卡片已被过滤、布局已变化、直接打开详情链接时，采用短淡入淡出，不强行飞回过期坐标。

**实施边界建议：** 第一版只覆盖“我的追番中一个已有本地条目 → 动漫详情 → 返回”。保留真实 URL、浏览器历史和打开新窗口语义；检验首次进入、返回后再次进入、快速取消、缺图、慢数据、窗口缩放。动画不可用仍要点了必达。播放器和影视空间等到该链路可靠后再扩展。

详情到播放器可以后续以封面／播放器容器扩展和周边变暗衔接，但不为了动画重复创建视频实例，不让退出动画阻塞进度保存。

## 4. 静态视觉升级：让封面、操作、资料有更清楚的主次

**番剧库首屏。** [globals.css](H:/追番网站-desktop-exe/src/app/globals.css:805) 的 catalog Hero 在桌面为 15rem；[BrowseClient.tsx](H:/追番网站-desktop-exe/src/app/(main)/browse/BrowseClient.tsx:560) 默认展开年份、分类、来源、类型、地区筛选。基线截图中卡片靠近首屏底部。这是信息分配问题，单独调 easing 改善有限。

建议保留季度切换、搜索、排序和已选条件摘要；把来源、细分类别等放进可展开区。完整筛选功能保留，当前默认的 TV／日本条件须在摘要中明确显示。标题氛围区适度压缩，不动首页沉浸式 Hero。验收目标是在常用 1280×900 下，默认状态能读到第一排卡片标题和状态。

**文字。** 当前默认 `--text-muted: #555555` 对 `#0a0a0b` 的计算对比度约 2.65:1，对 elevated 底色约 2.47:1。它适合非常次要的信息，关键进度、待看、下一集时间和操作提示需要更高层级。先调整语义使用，再决定是否改全局色值，避免全站一起变亮。卡片中文标题优先保证可读行高与合理截断，辅助信息不必都缩到 10–11px。

**材质。** 已有 [GlassPanel.tsx](H:/追番网站-desktop-exe/src/components/ui/GlassPanel.tsx:10) 的 default／elevated／inset 可复用。建议在当前方向内明确分工：内容底板安静，弹出操作面板有浮起感，输入／笔记区内嵌。精细边缘、层间差和留白比普遍加 blur 更值得优先做。

**海报。** BrowseCard 为 3:4，AnimeCard 为 16:9，Hero 又是全幅裁切。共享封面时需要处理同一张图在不同容器的裁切连续性，不能简单缩放一张竖海报铺满横屏。当前截图没有真实素材支撑裁切判断，这部分需要选长标题、人物近景、暗色与明亮海报实测。

## 5. Hero 与列表：减少互相独立的“表演”

[HomeHero.tsx](H:/追番网站-desktop-exe/src/components/features/HomeHero.tsx:135) 的背景交叉淡化为 600ms；标题为 450ms＋50ms delay，元数据为 400ms＋120ms delay，按钮又独立播放。标题和元数据通过 key 重建，未像背景一样保留完整退出节点。建议按一次“切换作品”编排：旧标题淡出、新画面接住、新标题入场；按钮区尽量稳定。保留已有悬停／焦点暂停轮播机制。

Hero 原生图片没有图像完成后再换场的协调状态。建议提前准备下一张，未准备好时保留当前画面或明确占位；不要让动画按时结束但新图尚未出现。是否值得额外预加载以实际资源和启动体验为准。

[TodayOrUpcomingSection.tsx](H:/追番网站-desktop-exe/src/components/features/TodayOrUpcomingSection.tsx:141) 使用 `mode="wait"`，退出 300ms 后再进入 300ms；两个视图都从右侧进入、向左退出。建议让“查看预告／返回今日”方向互逆，并缩短完整内容交接时间。高度差要平滑接住，不能造成下面区域突然跳动。

[LibraryClient.tsx](H:/追番网站-desktop-exe/src/app/(main)/library/LibraryClient.tsx:259) 有 40ms 列表 stagger，[useCardGlow.ts](H:/追番网站-desktop-exe/src/hooks/useCardGlow.ts:66) 还有延迟 orbit。筛选会重新绑定观察与进场逻辑。建议保留既有 orbit 品牌基线，将“首次进入”和“改筛选／更新状态”分开：后者强调变化的项目，不每次重播装饰。

卡片已有倾斜、升起、图像放大、扫边、跟随高光和底部浮层。[useCardGlow.ts](H:/追番网站-desktop-exe/src/hooks/useCardGlow.ts:5) 的 TILT_MAX=8 经中心差值计算，实际每轴极值约 ±4°，不能误报为 ±8°。当前回正 520ms、跟随 180ms 是 CSS 曲线。建议先试更轻的跟随／回正与降低复合高光竞争，而不是增加倾角或弹跳。实际是否存在性能问题需要测量，不能凭属性数量断言卡顿。

## 6. 保留的基线与验收

继续保留：全站主题强调色、详情局部番剧色、非链接 article 上的 orbit 宿主、Radix 锁滚修复、已正确延迟卸载的 Toast、播放器侧栏开关生命周期。不要再把登录视频序列当作本次主战场：桌面版以静默本机会话进入产品。

减少动态效果需要覆盖实际 Motion 位移。目前 HomeHero 虽调用 useReducedMotion，标题与元数据仍固定 y:10／y:8；今日／预告和追番网格也有固定 Motion 位移。CSS 降级不等于这些 JS 动画自动消失。保留必要的状态辨认，关闭大位移、倾斜和弹跳。

建议顺序：先修弹窗退出和开关连续操作；再做单条卡片→详情试验；并行准备番剧库首屏静态对比稿；最后扩展 Hero、播放器和跨空间过渡。不要先全站换动效库。

验收以具体动作判断：快速关开不闪断，返回保持上下文，慢资料不拖住点击反馈，缺图不出现空洞，减少动态效果有效，1180px／1280px 桌面窗口及配对 Safari 场景可操作。60fps 是项目目标，本轮没有测出已达标或不达标。

## 2026-09-13 勘误与证据边界

本节补充原审计之后取得的参考证据，不改写上文在 `e46b8ad` 基线时看到的 Bandi 状态。上文“没有 stiffness／damping／mass 物理弹簧”只适用于 **VibeHub 桌面目录卡片 ↔ 详情的主共享转场**：固定版的 `morph` 为 450ms、`cubic-bezier(.22,1,.36,1)`；[固定版源码定位台账](<K:/网站复刻/vibe-hub-clone/source-evidence/2026-09-12-refstudy/SOURCE-LOCATIONS.md>) 另确认移动端详情左右滑动的 settle 使用 `stiffness:430`、`damping:42`、`mass:.78`。后者不是桌面卡片进出参数，也不是当前线上移动端的实测。

“共享封面”指浏览器把旧卡片与新详情中同名元素的**截图快照**做几何插值；卡片 DOM 没有被原地搬到详情。参考固定版的旧 root 180ms 淡出、新 root 延迟 100ms 后 300ms 淡入、详情正文延迟 110ms 后 320ms 入场，属于 2026-09-06 镜像的构建源码时间线，不得和 [2026-09-12 线上／本地运行观察](<K:/网站复刻/vibe-hub-clone/source-evidence/2026-09-12-refstudy/RUNTIME-OBSERVATIONS.md>) 混写成同一部署的逐帧测量。

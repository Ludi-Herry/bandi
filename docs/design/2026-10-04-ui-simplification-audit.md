# UI/交互简化审查：奥卡姆剃刀 × 第一性原理 × 消融实验

> 日期：2026-10-04。范围：全部页面、导航、组件、用户可见文案与装饰体系。只读代码审计，未改任何文件。

## 0. 方法

**第一性原理**：这个产品只回答用户三个问题——「今天看什么、看到第几集、下集什么时候更新」，外加把单集下载下来并播放。逐元素追问：它帮用户回答哪个问题？答不上来的进消融候选。

**奥卡姆剃刀**：无必要不增实体。落到 UI 上四条：同一动作不需要两个入口；同一概念不需要两个名字；同一数据不需要两种图形；装饰必须自证用户能感知的收益。

**消融实验格式**：删除 X → 断什么 → 有没有替代路径 → 结论（删 / 合并 / 保留）。

**正向参照**：`/stats` 是全站最克制的页面——无 Hero、无粒子、无 glow，信息层级一致。它证明同一设计系统下可以做出不杂乱的页面，后面所有建议都有现成的站内基准。

正向防误伤：播放 8 处入口、找资源 5 处入口、刷新资料 4 个 scope 属**情境化合理重复**（用户在任何"看到内容"的地方都能直接操作），剃刀不剃它，本文不列为问题。

## 1. 一句话结论

最该先动的不是视觉装饰，而是**功能堆叠与文案黑话**；视觉层面最大单笔浪费是 anime-card-glow 全局体系；另有 4 块死代码/不可达页面可以零风险直接删。

## 3. B 级消融候选：外围自包含功能（删了只断自己，裁决交给你）

| 功能面 | UI 占用 | 删后断裂 | 消融判断 |
|---|---|---|---|
| 角色 /staff /character 页 + 详情页 credits Tab | 详情页一个 Tab 区 | 仅自身 + bangumi.ts 两个死函数 | 耦合极小。**若你平时不点人物页，可删**；爱看声优表则留 |
| 通知菜单（铃铛） | 导航右侧一个 icon | 仅自身；漏看/今日更新首页本来就有 | 与首页"漏看提醒"信息源重复，属同一需求的第二个入口。**可删，首页保留** |
| /profile 个人资料 | 用户菜单第一项 | 显示名回退 username | 单机应用里"个人中心"价值低。**可删** |
| 外部 qBittorrent 兼容模式 UI（QbitSetupGuideDialog + 设置页外部诊断卡） | 设置页一个区块 + 下载页一个卡 | 仅自身；受管 qBit 不受影响 | 桌面版零配置是它的卖点，外部诊断把"双引擎"概念塞给单机用户。**建议删 UI 保留底层，或折叠为"高级"** |
| 主题切换菜单 | 导航 Palette 下拉 | appSettings `user_theme` 变死行；ThemeSync 有导航后保活职责要一并处理 | 面小成本低；多主题是你设计系统的一部分，**建议保留但可减主题数** |
| 影视区（/cinema 三页） | SpaceSwitcher + 整组导航替换 | 最大外围面（lib 层约 5.8k 行），但 douban/media-compat/file-manager 与动漫共享，**只能减入口不能删库** | 不删功能本身；若影视用得少，可把 SpaceSwitcher 收起、默认不开第二空间，首染减半 |

## 4. C 级：合并而非删除（重复入口 / 一词多义）

1. **番剧详情页按钮排最多 6-7 个并列**（继续观看 / WatchStatusMenu / 订阅 / 刷新资料 / 下载管理 / Bangumi / 长门番堂，`anime/[id]/page.tsx:226-281`）。低频维护操作与最高频"继续观看"同级同排。→ 保留 1 个主 CTA + 观看状态，其余进 `•••` 溢出菜单。
2. **「追番」双语义**：AnimeSubscriptionButton（订阅=自动下载）与 WatchStatusMenu（观看状态）同页并列。→ 合并为一个控件，或把"订阅"改名为"自动下载"消歧。
3. **Bangumi 外链 ×2**（详情页 CTA 区 + 侧栏 RelatedResourcesPanel 同一 subject）。→ 留侧栏，删 CTA 区那个。
4. **下载管理入口 ×3**（主导航恒在 + 详情页条件链接 `anime/[id]/page.tsx:258` + 本地库空态链接）。→ 主导航已恒可用，详情页那条可删。
5. **影视补全三个名字三种粒度**（「刷新资料」/「刮削元数据」/「补全全部元数据」）。→ 统一叫「补全资料」，粒度靠位置表达。
6. **更新气泡 vs 设置中心双入口**：同状态机同动作。桌面应用惯例如此，**保留**。
7. **RSS 源管理 UI**：**不建议删**——删了自动下载 cron 变成无 UI 的暗自动化，出问题用户更无从下手。建议降级为设置页"高级"折叠区块。
8. Nav 宽/窄屏把同一组组件树写了两遍（`Nav.tsx:343-376` vs `548-580`，主题菜单同样两遍）。非用户可见问题，但每加一个导航项要改两处——代码级 DRY 待办。

## 5. 文案专项治理

### 5.1 黑话→人话（重灾：下载管理页、设置页）

| 现状 | 位置 | 建议 |
|---|---|---|
| 「检查 QBIT_USER / QBIT_PASS 是否和 qBit Web UI 一致」 | `admin/downloads/Client.tsx:753` | 「下载服务登录信息不一致，点左侧修复」——环境变量名永不上屏 |
| 「外部 qBittorrent 4.6.x 可连接，Web API 2.x」 | `AutomationSettingsClient.tsx:670` | 删版本号 |
| 「刮削元数据」 | `CinemaEnrichButton.tsx:148` | 「补全资料」 |
| 「通过事件流确认看完」 | `stats/page.tsx:128` | 「今年还没有看完的番剧」 |
| 「支持 Mikan / Nyaa / 动漫花园等 RSS 2.0 feed」 | `RssEditDialog.tsx:76` | 「支持常见番剧订阅站」 |
| 「下载完成后暂停 torrent」「做种」 | `Client.tsx:735` | 「下完自动停止上传」 |
| `alert("删除失败，看控制台")` | `LibraryClient.tsx:207` | 换 toast：「删除失败，请再试一次」 |
| 「磁链已存在」 | `EpisodeSourceDialog.tsx:555` | 全应用唯一一处"磁链"，→「这集已经在下载队列里」 |

### 5.2 术语二选一（全站统一）

- **在看** / 正在看 → 留「在看」（`LibraryClient.tsx:36` vs `library/page.tsx:106`）
- **看完** / 已看完 → 留「看完」
- 下载完成 / 已完成 / 排队中 / 等待下载 → 下载状态只留「下载完成」「下载中」「等待中」「失败」
- 想看 / 已收藏 → 留「想看」（`BrowseClient.tsx:368` vs `SearchCommand.tsx:544`）
- 番剧 / 动漫 / 动画混用 → 界面统一「番剧」，影视空间统一「影视」

### 5.3 删掉模式泄漏（单机用户不需要知道的分类）

- 「桌面版自动管理」「桌面版正在恢复」——用户只有桌面版，"桌面版"三字全删。
- 安装形态分类上屏「Windows 安装版/便携版/macOS…」`DesktopUpdateSettings.tsx:232`——删，或压成一行小字。
- Mac 配对流程残留（`LocalServerSessionGate.tsx:111`、`DesktopDownloadSettings.tsx:49`）——Windows 构建不该出现。
- 「当前浏览器拒绝了全屏请求」`PlayerClient.tsx:934`——桌面壳里不说"浏览器"。
- 「Bandi 无法建立本机会话」`DesktopSessionGate.tsx:33`——"会话"是工程词，→「启动失败，点击重试」。

## 6. 布局密度治理（逐页）

- **首页**（5 个竞争区块，达阈值上限）：今日更新 / 可继续播放 / 漏看三条信息源同质——都在回答"今天看什么"。→ **合并为一个「今天」区块**，按"能直接播 > 已更新未下载 > 待放送"排序；本季新番轨道保留。Hero 单块约 8 组信息（3 层遮罩+元行+68px 标题+评分+进度+2 行简介+4 tags+2 按钮+缩略图轨道+6s 轮播），至少删「本季热门」假标签、压缩简介为 1 行。
- **番剧详情**（约 7 区块）：按 §4.1 收纳按钮排；右栏 4 面板里「社区口碑」单卡 4 来源行 ×（分+尺度+人数/排名+抓取时间）过密，抓住时间删或收 tooltip。低频的"刷新资料/下载管理"降出第一视觉层。
- **下载管理**（单行 ~10 元素，全站之最）：每行只外露播放 + 一个主操作，暂停/重下/删除进 `•••`；「清空列表」高危操作与状态 tab 分行。
- **/cinema**（6-7 区块）：MoodPicker 心情选片从页头降级进筛选条；追随更新 3 个子区块与动漫首页"今天"合并思路一致。
- **/browse**：25 个类型 chip 收进"更多筛选"默认折叠；「刷新资料」「来源标注」等维护型操作与浏览筛选分两层。
- **EpisodeSourceDialog**：别名管理 chips×3 行是高级功能，折叠为"搜索不准？修正匹配"；打开弹窗第一屏直接是候选列表。
- **AnimeCard**（约 8 视觉层、最多 3 个 chip 同卡）：保留封面+标题+进度，chip 只留优先级最高的一个（待看 > 状态 > cornerLabel）。
- **/settings「数据与维护」区**大部分是占位（自述"高风险操作后续单独设计"）：要么实现，要么删占位面板，不要留一个形同公告栏的空区。

## 7. 装饰体系消融（投入 vs 用户可感知收益）

| 装饰 | 覆盖面 | 用户收益 | 消融判断 |
|---|---|---|---|
| **anime-card-glow 全局体系**（2.2s 扫描环 + 鼠标描边 + 3D tilt + glare） | ~10 个网格页面全部卡片，`globals.css:2154-2433` 约 280 行 | 仅 hover 反馈；还付了 Chrome conic 冻结兼容 hack（`AnimeCard.tsx:78` 注释） | 全站最大单笔装饰投入。**建议：删进场扫描环 + tilt glare，只留鼠标边缘描边**；卡片观感几乎不变，删约 2/3 代码 |
| EmberBackground 粒子 | 仅首页 | 氛围 | 保留但可议：65 粒子×shadowBlur 每帧重绘是明确 GPU 成本；低配路径已有降级，可默认降粒子数 |
| SpinningCounter（187 行）/ NumberPop | /stats、通知、下载计数 | 静态数字滚动/弹跳，收益近零 | 数字不大的场景直接删动画，改普通文本 |
| 动态取色（AccentProvider + 详情页 `--anime-*`） | 全站 accent + 详情页 | 品牌核心"封面取色"，设计系统已规范化 | **保留**——这是产品记忆点，收益明确 |
| DuskBackdrop 三段登录视频 | 见 §2，已不可达 | 无 | 随 LoginShell 一并删 |

设计红线对照：未发现蓝紫主题、>12px 圆角、廉价 glow 违规——当前问题不是风格越界，是**量**越界。

## 8. D 级：不建议删（消融代价大于收益）

- **/stats + watchEvents 是一对**：watchEvents 写入嵌在 3 条核心 API（播放进度、追番、标记集数）里，删表要动核心写路径；stats.ts 还被 /profile 和 /library 页 Hero 引用。且 /stats 本身是克制页面的正向样板。**保留**。
- **DesktopUpdateNotice**：与打包流水线、app-update 状态机耦合，删了要同步裁 preloading/打包侧。**保留**。
- **RSS 管理 UI**：见 §4.7，保留但降级。

## 9. 建议执行顺序

- **P0 清死代码（半天，零风险）**：§2 全部 + ParticleField/AccentSetter/orbit-demo。
- **P1 文案统一（1-2 天，高收益低风险）**：§5 三张表——黑话替换、术语二选一、删模式泄漏。
- **P2 入口合并（2-3 天）**：§4 的 1-5；详情页按钮排、双语义"追番"是用户每天都撞见的。
- **P3 密度治理（逐页过稿）**：§6，先首页"今天"合并与下载行收纳。
- **P4 消融决策（等你拍板）**：§3 B 级功能面（通知菜单、profile、人物页、外部 qBit UI、影视空间开关）+ §7 glow 体系删减幅度。

每一步独立可交付、可回滚；P0-P2 不需要视觉重设计，P3 才进入逐页视觉调整。
